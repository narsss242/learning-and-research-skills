# 多源交叉校对

适用：用户追加同一音视频的另一平台文稿、字幕PPT、课件，要求合并校对或重写总结。

默认仍只用得到大脑服务。额外材料由用户提供或已在本地存在时读取即可，不为凑齐多源而调用听悟或要求用户另做一份转写。

## 先确认材料性质

- 保留旧稿和原始JSON，为本轮另建来源目录及修订稿，不覆盖已有人工作业。记录文件名、哈希、时长／覆盖范围和来源日期。
- 看真实文件格式，不只看后缀；网盘导出的`.doc`可能实际是DOCX ZIP。
- PPT可能全部是视频字幕截图，提取文本为空不等于没有内容。检查图片、页序与slide关系；OCR只用于定位，关键字幕必须目视原图。PPT未覆盖的疑点，可从同一原视频提取连续帧；按时间范围一次批量提取，避免每秒启动一次ffmpeg。
- 另一份“课件”若实际是视频画面，不把它当独立的专业事实来源。

## 得到大脑

遵从用户全局的得到大脑流程，先读其Obsidian流程笔记，沿用桌面登录态。凭据只在进程内使用，不导出整库／令牌／签名链接。

- 查最新笔记时，桌面实际列表参数为`limit`、`since_id`、`sort=create_desc`或`edit_desc`；不是`page`。全文搜索用`/voicenotes/web/notes/search?page=1&page_size=20&query=...`。
- 用户可能已上传音频但尚未点击生成笔记。先核对最新笔记的标题、创建时间、处理状态及`/notes/generating-count`，不要把搜索为空误判成登录失效，也不要在用户已提交后另行上传重复任务。
- 分别导出完整`content`（智能整理）与`/notes/{id}/original`的逐句转写。转写的`content`为JSON字符串时，解析`sentence_list`，核对`task_status`和时间覆盖。
- `?show_opt_asr=true`可能返回空列表，而原始转写已完成；如实使用可用原稿，不能把空优化稿算为另一份校对证据。
- 新笔记还在生成时，可以先用已完成的原始转写开展校对，稍后再读智能总结。保留笔记ID、标题、日期和必要内容，附件授权URL不写入工作记录。

## 比较与定稿

1. 以已有句段及来源索引为骨架，对新增文本做顺序对齐；标准化文本只用于匹配，不直接替代原文。差异量和相似度只辅助定位，不能代表校对质量。
2. 逐段看专名、英文、漏词、否定、数值／范围、单位和角色。材料有冲突时查看上下文与字幕，不按平台多数票定稿；同音误识别可能跨平台一致。
3. 说话人交接按[发言人区分与交接核对](speaker-attribution.md)，结合实际可用的原平台标签、连续问答和相应画面核对；没有声学结果不自动调用听悟。字幕若不标说话人，仅凭字幕文字不能证明人名。拆分保留来源ID和原时间，不伪造精确边界。
4. 先解决原有待核项，再看新材料暴露的错误。未覆盖或无法定词的短插话只留下最小局部标记及时间，不删句假装解决，也不扩大成整段缺失。把原“未辨清”恢复为明确附和时，记录新依据。
5. 保留口述的自我修正和明显未完句。涉及市值、上市、预测、医疗、技术安全等，只校正实际说法，不借校稿替受访者修观点；“今年／去年／明年”需以录制日期确定，不能默认等于整理日期。

## 重写提要及交付

- 从校对正文重新归纳；平台智能总结只作主题检查。特别防止摘要把有条件的判断变成绝对事实、把广泛板块判断缩成单一标的建议、把已有获奖人扩成奖金已到账、把主持人提问写成受访者主张。
- 分开原话、自述计划、预测、整理者推断；摘要按主题组织并给真实正文时间点，平台自动章节的时间可能错配。
- 按用户顺序交付，例如“总结提要→完整原稿”；保留发言人和时间定位。记录来源、修改前后与理由，核验原来源片段覆盖、章节数量和剩余待核数。
- 做PDF时沿用PDF技能的生成、逐页渲染及目视检查，最后核对正文可检索且无漏段。报告真实完成范围，不将字幕目视核验称为人工回听。
