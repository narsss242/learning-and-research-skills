# 发言人区分与交接核对

该步骤在得到大脑默认流程内执行。需要发言人标签，不意味着需要或获准启用通义听悟。

## 先辨别平台标签能证明什么

- 保存原始`speaker_id`、`speaker_name`及对应句段，不先抹平标签。查看多个远隔片段，确认编号是否稳定、有无同一人被拆成多个编号或多人混为一人。
- 所有段落同为0、姓名为空、平台只估计“约2人”，都不能当成已完成声学分离。用户自己是参与者时也不擅自标`(我)`。
- 区分两种成果：有可靠平台声学标签的“声学分离并做角色映射”；依据问答、字幕和明确角色整理的“按语境区分阅读版”。交付说明实际使用哪一种，不把后者说成声纹识别。

## 从编号到角色／姓名

1. 先找多处明确的提问、自我介绍、称呼和第一人称经历，建立“编号→主持人／受访者／发言人A”等映射，再决定能否使用姓名。
2. 在访谈开头、中部、后部复核映射稳定性，防止机器编号漂移或片头预告剪辑造成误接。
3. 姓名来自明确介绍、字幕姓名或已确认身份关系，不通过人脸猜姓名。画面可辅助核对某处是否换人，不能单独证明身份。
4. 没有身份依据时使用“发言人A／B”等标签；标签不足时提供可确认的角色，不按问题末尾问号或两人轮流说话的假设机械分配。

## 重点复核交接

- 重点检查短附和（“对”“是的”“OK”“明白”）、复述问题、反问、打断、重叠发言，以及一个平台句段里已经包含两人的问答。
- 对疑点查看前后数秒的连续上下文、已有字幕和可用原音；字幕不带姓名时，结合原有平台标签、已确认角色与相应画面判断，单张截图不足时扩大范围。
- 机器换人可能切在单词或问题中间；按实际话轮修边，不逐字盲从SpeakerId。分开的问句、回答和附和各列一行，避免把主持人的问题写成受访者观点。
- 多人同说可标“重叠”；仍无依据的短句标“交接未定”并留时间。先尝试解决，再保留最小局部疑点，不强行归给一人。

## 可追溯与验收

- 每条修订保存来源笔记ID／文件、句段索引、原时间、原标签、新标签及依据；修改说话人不顺便改写未核实的文字。
- 用已有校对稿对齐新标签时，标准化文本仅用于匹配，校改文字保留。匹配率高不代表交接正确，仍需复核边界。
- 拆句后的时间如共用来源片段起点，应明示不是精确换人时刻；没有实际字级对齐结果时不伪造毫秒边界。
- 检查所有原句段有对应、没有因拆人而丢句或重复整句，检查已确认姓名全篇一致，并报告残余不确定范围。

如得到大脑标签不足，先完成能可靠确认的角色整理并说明限制。用户另提严格声学分离等需求时先说明现有能力；仅在其明确选择通义听悟补充方案后，才进入备用流程。
